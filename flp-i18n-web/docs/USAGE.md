# Git Control Room 使用文档

> 适用版本：1.0.0  
> 配套文档：[部署文档](DEPLOY.md)

Git Control Room 用于在本机集中管理多个 Git 仓库：克隆、导入、更新、切换分支、查看状态，全部在一个页面内完成，不上传任何数据。

---

## 1. 界面总览

```text
┌──────┬──────────────────────────────────────────────────────────────┐
│ 图标 │  LOCAL MACHINE / REPO CONTROL       [设置] [LIVE 30S] [刷新] │
│  栏  ├──────────────────────────────────────────────────────────────┤
│      │  CONTROL ROOM / 01                                           │
│      │  Repository control.                                         │
│      │  在本地统一克隆、同步与切换分支……                           │
│      │  [添加项目] [导入本地] [批量导入] [切换分支] [全部更新]      │
│      ├──────────────────────────────────────────────────────────────┤
│      │  搜索框                        [全部][有改动][待同步][干净]… │
│      │  项目列表                                   │ 运行状态统计  │
│      │  01  flm-base …                             │ 操作记录      │
│      │  02  …                                      │ 快捷键        │
│      └──────────────────────────────────────────────────────────────┘
```

主要区域：

- **顶栏**：「设置」按钮、`LIVE 30S` 自动刷新开关、手动刷新按钮。
- **主操作区**：添加项目、导入本地、批量导入、切换分支、全部更新。
- **工具栏**：关键词搜索、状态筛选、排序。
- **项目列表**：每行显示名称、仓库地址、当前分支、状态、最近提交及操作按钮。
- **右侧栏**：TOTAL / DIRTY / DRIFT / OFFLINE 统计、克隆根目录、最近操作记录、快捷键提示。

---

## 2. 状态含义

| 标签 | 含义 | 判定条件 |
| --- | --- | --- |
| `CLEAN` 干净 | 无改动且已同步 | 仓库可用、无未提交改动、ahead/behind 均为 0 |
| `DIRTY` 有改动 | 工作区有未提交变更 | `git status` 检测到改动（优先级高于 DRIFT） |
| `DRIFT` 待同步 | 本地与远端存在差异 | ahead 或 behind 大于 0（基于最近一次 fetch 结果） |
| `OFFLINE` 离线 | 仓库不可用 | 本地目录不存在显示 `MISSING`；非 Git 仓库或命令失败显示 `ERROR` |

列表中的同步列还会显示：

- `↑2 ↓1`：领先远端 2 个提交、落后 1 个提交。
- `3 处改动`：工作区改动数量。
- `in sync`：完全同步。
- 分支名显示为 `detached` 时表示当前处于游离 HEAD 状态。

> ahead/behind 来自最近一次 fetch。若不点「更新」，远端新提交不会自动反映到统计中。

## 3. 添加项目

点击主操作区 **添加项目**（快捷键 `N`），填写：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 仓库地址 | 是 | 支持 HTTPS、SSH 或本地路径；会自动过滤首尾空白 |
| 本地目录 | 否 | 指向已有克隆时直接「挂载」，不会重复克隆；目录不存在时会克隆到该位置；支持 `~/` |
| 显示名称 | 否 | 留空时从仓库地址推导 |

行为说明：

1. 不填本地目录：克隆到当前克隆根目录（默认 `data/repos/`），目录名由仓库名生成；重名时自动追加 `-2`、`-3`。
2. 本地目录已存在且是 Git 仓库：直接挂载，返回「已添加项目」。
3. 本地目录已存在但不是 Git 仓库：返回错误，不会覆盖或写入。
4. 同一仓库地址或同一本地目录已在列表中：返回 409「已在列表中」。

按钮在请求期间显示「克隆中…」，克隆超过 5 分钟会超时终止。

## 4. 导入本地项目

用于把**已经下载好**的仓库加入控制台。点击 **导入本地**（快捷键 `I`）：

1. 在「本地路径」中输入目录，或点击 **浏览…** 打开系统目录选择器。
2. 如果勾选的是仓库内的任意子目录，服务端会自动向上定位到仓库根目录（`git rev-parse --show-toplevel`）。
3. 显示名称留空时，优先使用 `origin` 远程地址推导，否则使用目录名。
4. 点击 **导入项目** 完成导入。

规则与提示：

- 只接受 Git 仓库；普通目录会提示「该目录不是 Git 项目（未找到 .git 仓库）」，不会创建或修改任何文件。
- 路径支持 `~/`。
- 仓库地址优先取 `origin`，没有远程时使用本地路径作为仓库标识。
- 已导入过的仓库（按根目录或仓库地址判断）会返回 409。
- 目录选择器在服务端所在电脑上弹出：
  - macOS 使用系统「选择文件夹」窗口；
  - Windows 使用 PowerShell 文件夹选择框；
  - Linux 需要 `zenity` 或 `kdialog`，都没有时请手动粘贴路径；
  - 无桌面会话（SSH、纯守护进程）时无法弹出，请手动输入。

> 导入只登记路径，不会移动、复制或删除你的文件。

## 5. 批量导入

点击 **批量导入**，在文本框中每行填写一个仓库：

```text
git@github.com:org/api.git
https://github.com/org/web.git, /Users/you/work/web
/Users/you/projects/legacy
# 以 # 开头的行会被忽略
```

格式：

- `仓库地址`
- `仓库地址, 本地目录`（逗号或制表符分隔）
- 本地目录两侧的引号会自动去掉

限制与行为：

- 单次最多 50 个，并发 2 个。
- 逐条执行，单条失败不影响其他条目。
- 结果以列表形式显示「已克隆 / 已挂载 / 错误原因」。
- 全部成功时抽屉会自动关闭；部分失败时保留结果列表供查看。

## 6. 更新仓库

### 单个更新

在项目行右侧点击刷新图标，或在展开详情中点击 **FETCH & PULL**。

执行流程：

1. `git fetch --all --prune`；
2. 如果当前分支配置了 upstream，再执行 `git pull --ff-only`；
3. 没有远程仓库时跳过更新并提示；
4. 无法快进（本地与远端分叉）时 fetch 仍成功，但 pull 会报错，需要在仓库内手动 merge 或 rebase。

### 全部更新

点击 **全部更新**，对列表内所有仓库执行同一流程，并发 3 个。

- 按钮在过程中显示「更新中…」；
- 完成后弹出汇总提示，失败信息最多展示前 3 条；
- 展开中的项目会同步刷新分支列表。

> 工具不会自动 stash、merge 或 rebase，也不会强制覆盖本地改动。

---

## 7. 切换分支

### 单个项目切换

1. 点击项目行（或右侧分支图标）展开详情；
2. 在 LOCAL / REMOTE 分支列表中点击目标分支；
3. 本地不存在对应分支时，远程分支会以 `checkout -b <name> --track origin/<name>` 的方式创建本地跟踪分支；
4. 切换成功后列表与详情会自动刷新。

分支列表在首次展开时加载并缓存，点击 **REFRESH** 可重新拉取。

### 批量切换（按名称）

点击主操作区 **切换分支**：

| 字段 | 说明 |
| --- | --- |
| 分支名称 | 必填；不存在时会在所选仓库中创建 |
| 基线分支（可选） | 填本地分支名；本地不存在但 `origin` 上有同名分支时，会自动基于 `origin/<名称>` 创建 |
| 应用到 | 勾选需要操作的仓库，支持全选/清空 |

执行规则：

- 本地已有该分支：直接切换。
- 本地不存在：从基线分支创建并切换；未填基线时基于当前 HEAD 创建。
- 想跟踪远端已存在的同名分支：分支名称和基线都填同一个名称，例如都填 `feature/i18n`，会基于 `origin/feature/i18n` 创建跟踪分支。
- 分支名不合法或没有选择项目时，会在抽屉内提示。
- 工作区有未提交改动导致 Git 拒绝切换时，该仓库报错，其他仓库继续执行。
- 结果逐条显示「已创建 / 已切换 / 错误原因」。

> 注意：批量切换是「切换或创建」，不会删除分支，也不会重置本地改动。

## 8. 提交与推送

展开项目详情后，操作区提供两个按钮：

- **COMMIT CHANGES**：仅在工作区有改动（DIRTY）时可用；
- **PUSH BRANCH**：在仓库可用且不处于游离 HEAD 时可用。

### 提交改动

点击 **COMMIT CHANGES** 打开提交抽屉：

1. 抽屉顶部显示项目路径、当前分支与待提交改动数量；
2. 填写提交说明（必填，最多 4000 字符）；
3. 可选勾选 **提交成功后推送到远程**；
4. 点击 **提交**。

执行流程：

1. `git status --porcelain` 确认存在改动，否则提示「没有可提交的改动」；
2. `git add -A` 暂存新增、修改与删除的全部改动；
3. `git diff --cached --name-only` 确认暂存区非空；
4. `git commit -m "<提交说明>"`；
5. 勾选推送时，继续执行推送流程。

提交成功后提示短哈希与文件数，并写入操作记录；如果勾选了推送但推送失败，会提示「已提交，但推送失败」，提交本身仍然有效。

> 提交前请确认已配置 Git 身份（`user.name` / `user.email`），否则 Git 会拒绝提交。

### 推送分支

点击 **PUSH BRANCH**，或在提交时勾选推送：

- 当前分支已配置 upstream：执行 `git push`；
- 未配置 upstream：自动选择 `origin`（没有则用第一个远程），执行 `git push -u <remote> <branch>`，成功后建立跟踪关系；
- 没有远程仓库、游离 HEAD 或找不到 Git 仓库时直接报错，不会修改任何内容。

推送成功后提示分支与 upstream，项目状态会刷新（`ahead` 归零）。

### 常见错误

| 提示 | 原因与处理 |
| --- | --- |
| 没有可提交的改动 | 工作区干净，无需提交 |
| 请填写提交说明 | 提交说明为空或只有空白字符 |
| 游离 HEAD，无法推送 | 先切换到一个分支再推送 |
| 没有配置远程仓库 | 在仓库内添加 remote 后再推送 |
| `non-fast-forward` / `rejected` | 远端有本地没有的提交；先在仓库内 pull --rebase 或 merge，再推送 |
| 认证失败 / `Permission denied` | 服务端不会交互式询问凭据；先配置 SSH key 或 credential helper |

> 本工具只执行普通提交与推送，不会自动 rebase、merge、force push，也不会跳过 Git hooks。

## 9. 查询、筛选与排序

### 搜索

搜索框（快捷键 `/`）会忽略大小写，匹配以下字段：

- 项目名称
- 仓库地址
- 本地路径
- 当前分支
- 最近一次提交说明

### 状态筛选

| 按钮 | 对应状态 |
| --- | --- |
| 全部 | 所有项目 |
| 有改动 | DIRTY |
| 待同步 | DRIFT |
| 干净 | CLEAN |
| 离线 | OFFLINE（MISSING / ERROR） |

按钮后的数字为对应数量，实时随列表更新。

### 排序

- **名称 A–Z**：按名称本地化排序。
- **最近提交**：按最近提交时间倒序。
- **仓库状态**：离线 → 有改动 → 待同步 → 干净，同状态按名称排序。

没有匹配结果时可点击 **清除筛选** 一键还原。

## 10. 项目详情

点击项目行，或聚焦后按 `Enter` / `Space` 展开：

- **LOCAL PATH**：本地目录。
- **UPSTREAM**：上游分支，未设置时显示「未设置」。
- **LAST COMMIT**：短哈希、作者、提交时间。
- **REMOTE**：`origin` 远程地址，未设置时回退为登记的仓库地址。
- **BRANCHES**：本地分支与 `origin` 远程分支列表，点击即可切换。
- **COPY PATH**：复制本地路径到剪贴板。
- **REFRESH**：重新读取分支列表。
- **COMMIT CHANGES**：提交全部改动（仅 DIRTY 时可用，见第 8 节）。
- **PUSH BRANCH**：推送当前分支（见第 8 节）。
- **FETCH & PULL**：更新该项目。
- **REMOVE FROM LIST**：从列表移除。

仓库不可用时，详情顶部会显示具体错误（目录不存在、不是 Git 仓库等）。

---

## 11. 移除项目

点击项目行的删除图标，确认后从控制台移除。

- **只移除记录，不会删除本地目录和文件。**
- 同时会清除该项目在本页面的分支缓存。
- 若要重新纳管，可通过「添加项目」挂载或「导入本地」再次导入。

---

## 12. 设置默认克隆目录

点击顶栏 **设置**（快捷键 `S`），或右侧栏 CLONE ROOT 旁的 **更改**：

| 项 | 说明 |
| --- | --- |
| 当前克隆目录 | 显示当前生效目录；内置目录显示为 `data/repos` |
| 默认本地目录 | 留空表示使用内置 `data/repos/`；支持 `~/` |
| 保存设置 | 目录不存在会自动创建，并检查是否为目录、是否可写 |
| 恢复默认 | 清空自定义目录，立即切回内置目录 |

规则：

1. 不能使用文件系统根目录（如 `/`）。
2. 路径包含控制字符或过长（>1024 字符）会被拒绝。
3. 目录必须可写，否则提示无权限。
4. 只影响**之后**的克隆；已添加项目的本地路径不会变化。
5. 设置保存在 `data/settings.json`，重启后仍然有效。
6. 右侧栏 CLONE ROOT 会实时显示当前目录，自定义时标记为 `CUSTOM`。

## 13. 自动刷新与操作记录

### LIVE 自动刷新

- 默认开启，每 30 秒读取一次所有仓库状态。
- 以下情况会自动暂停本轮刷新：浏览器标签页不可见、正在加载、抽屉或弹窗打开。
- 点击 `LIVE` 可暂停/恢复，状态保存在浏览器 `localStorage`（`gcr:live`），每个浏览器独立。
- 手动刷新按钮（快捷键 `R`）不受开关影响，随时可用。

### 操作记录

右侧栏记录最近 8 条操作：添加、导入、更新、切换分支、修改设置、移除、错误。

- 保存在浏览器 `localStorage`（`gcr:activity`），不是服务端日志；
- 换浏览器或清除站点数据后记录会丢失；
- 服务端错误日志输出在启动终端（或守护进程日志文件）中。

## 15. 移动端

- 窄屏下左侧图标栏隐藏，操作按钮自动换行。
- 顶栏设置按钮收为图标（文字隐藏），避免拥挤。
- 抽屉变为全宽，分支详情改为单列。
- 目录选择器仍在**服务端电脑**上弹出；若通过手机或 SSH 隧道访问，请直接输入路径。

## 16. 常见问题

**Q：导入时报「该目录不是 Git 项目」？**  
确认目录中存在 `.git`，且路径指向的是真实目录；仓库内的子目录可以直接选，系统会自动定位到根目录。

**Q：为什么更新后 ahead/behind 没有变化？**  
ahead/behind 基于 fetch 结果。若更新失败或未配置上游分支，统计不会变化；先确认 `git -C <dir> status -sb` 的 upstream 配置。

**Q：更新提示无法快进（Not possible to fast-forward）？**  
本地与远端已分叉。工具只做 `--ff-only`，请在仓库内手动处理（如 `git pull --rebase` 或 `git merge`）。

**Q：切换分支失败？**  
常见原因是工作区有未提交改动与目标分支冲突。先 commit 或 stash 再切换。

**Q：私有仓库克隆/更新失败？**  
服务端禁用了交互式凭据提示。请先在终端配置好 SSH key / SSH Agent / credential helper，并确认 `git clone` 可以免交互成功。

**Q：为什么「全部更新」跳过某些仓库？**  
这些仓库没有配置远程仓库，属于正常跳过，不会报失败。

**Q：移除项目会删除我的代码吗？**  
不会。只删除控制台中的登记记录，本地目录保持不变。

**Q：换一台电脑还能看到原来的列表吗？**  
不能。数据只保存在当前电脑的 `data/projects.json`，属于纯本地工具，没有云端同步。

**Q：浏览器关了，后台还在跑吗？**  
服务由启动它的终端/进程管理器维持，关闭浏览器不影响；需要停止时在终端按 `Ctrl+C` 或停止对应服务。

**Q：项目显示 `MISSING` 怎么办？**  
本地目录被移动或删除。把目录移回原位置，或从列表移除后重新导入/挂载。

**Q：项目显示 `ERROR` 怎么办？**  
展开详情查看错误。常见原因是目录已不是 Git 仓库，或 Git 命令执行失败。

**Q：页面字体和截图不一致？**  
界面字体来自 Google Fonts，离线时回退为系统字体，不影响任何功能。
